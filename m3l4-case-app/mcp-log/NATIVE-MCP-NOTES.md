## Finding for each work item

### Item 3: a supported read-only status label

No supported non-interactive chip exists. `IgxChipComponent` has `disabled` (greys out, so wrong for a normal
status), `selectable` (false by default) and `tabIndex`; there is no read-only mode. The app already sets
`[tabIndex]="-1"` so the chip is not a tab stop. `igx-badge` is documented as "a non-interactive status visual" with
`role="status"`, `type` (primary, info, success, warning, error), an icon and a value, and a note that colour must
not be the only cue. It is meant as a small count or dot beside another control, so using it here would change
size and shape on every screen; it was not tried. The `igx-chips-area` wrapper stays: it provides the listbox
role an option chip needs (axe flagged a chip without one in Round 1) and the docs offer no alternative.
Root cause of the old comment being wrong: a whole-value `[class]="expr"` is bound to a chip input that is named
`class` and unused, so it never reaches the element; `[class.name]`, `[ngClass]` and a static `class` all do.

### Item 5: stepper "NaN"

Reproduced on `igniteui-angular` 22.2.6. Template:

```html
<igx-stepper orientation="horizontal" titlePosition="end" [linear]="false">
  @for (s of state.scenes; track s.n) {
    <igx-step [active]="state.scene() === $index">
      <span igxStepTitle>{{ s.stepTitle }}</span>
    </igx-step>
  }
</igx-stepper>
```

(the component is `OnPush`). Seven indicators read **NaN** on load; after the first arrow-key press they read 1 to
7. The default indicator is `{{ index + 1 }}` and `index` returns `_index`, which `IgxStepperComponent.updateStepAria`
writes. Probable cause, read from the source and not proven: for steps made by `@for` the index is written after
the steps' views were first drawn (the `_steps.changes` handler runs it in a microtask), so `index` is undefined at
the first draw and nothing marks the step dirty afterwards. The stepper doc does not mention it; every
data-driven example in the doc passes an explicit `igxStepIndicator`. Screenshot: `round2-shots/work/stepper-no-indicator-22.2.6.png`
(not in git). The explicit `<span igxStepIndicator>` was restored.

### Item 6: `igc-theme-provider`

There is no doc for it (C6, C8, C10, C11); only the API entry (C9). **Adopted**:
`<igc-theme-provider theme="material" variant="dark" style="display: contents">` around `<app-ops-view>`, and
`configureTheme` removed from `main.ts`. Compared pixel by pixel with the `configureTheme` build at 1920x1080:
scenes 1, 2, 3, 5 (with all four reveals shown) and 7, and the overlay were **identical** (0 pixels differ). Control
test: a `bootstrap` / `light` provider changed the tile manager visibly on scene 5 (152,861 pixels) and changed
nothing on scene 3, so the provider does reach the tile manager, and **Grid Lite does not follow the provider**
(its colours come from the `--ig-*` variables the page's palette sets). Anything needing a Grid Lite theme change
has to go through CSS variables.

### Item 10: styles inside Grid Lite cells

A Grid Lite cell with a cell template is a custom element (`igc-grid-lite-cell`) with a shadow root, and the Angular
chips the template creates are moved into it. Document CSS does not normally reach in. It does here because:
`IgxGridLiteComponent` sets the host attribute `adopt-root-styles`; that turns on `adoptRootStyles` on each cell
(`igniteui-grid-lite/components/cell.js`: `_shouldAdoptStyles = adoptRootStyles && cellTemplate != null`); and the
cell's `AdoptedStylesController` (`igniteui-webcomponents/internals/controllers/adopt-styles.js`) clones every
stylesheet in `document.styleSheets` into the shadow root as constructable stylesheets, re-cloning on any change to
`<head>` (a `MutationObserver`). In the running page a cell's shadow root holds 21 adopted sheets, one of them the
whole global stylesheet (323 rules, including `.chip-nodata`) and the chip's `@layer ig.base` rules. So the global
theme rules, the `.chip-nodata` tokens and Angular's own emulated-encapsulation component styles all apply; custom
properties would have inherited through the shadow boundary anyway. Nothing about this is in any doc the tools
return (C22, C23). What I could not establish is the cause of the contrast failures in Round 1: Round 1's note says
axe found 1.9:1 for the derived light text on the grey chip, which is a chip-theme default (the derived foreground),
not something shadow DOM causes; a fix at that stage is the `text-color` token Round 1 already set.

*Supervisor's note, 13 Nov 2026:* a separate re-test did not reproduce the 1.9:1 figure. With the `text-color`
token removed, the derived text on the grey chip is black (about 8:1) and axe reports no contrast finding on
scenes 1, 3 and 5. The figure exists only in a code comment from Round 1, so the original cause stays unknown.
The input label's size, listed above as "kept", was afterwards replaced by the documented typography variable
`--ig-caption-font-size` (found by the M3 L5 session through `search_docs`), so that row is now "replaced".
The first row of the table is also superseded: `.topbar ::ng-deep .igx-navbar` matched no element (in
`igniteui-angular` 22 the `igx-navbar` class is on the host, the same element that carries `topbar`), so the bar
was always the library's default 3.5rem. The rule was removed as dead code; the M3 L5 session had found the same.

## What would have saved me time

1. **A "which components honour `--ig-size` / `--ig-spacing`" table**, or a note in `set_size` / `set_spacing`
   output when a component does not use `sizable()` / `pad()`. Both tools returned a confident CSS block for the
   stepper, banner and navbar, where it does nothing.
2. **`search_api` / `search_docs` that rank on the concept.** "chip read-only status label" returned charts and
   Excel classes with `platform: angular` set. A single identifier works (`configureTheme`, `IgcThemeProvider`);
   anything longer does not. Even a "did you mean" for the first result would help.
3. **Smaller answers.** `get_doc` of chip, badge and stepper is 8 to 12k tokens each, mostly demo code that repeats.
   A `section` argument for `get_doc` (as `get_api_reference` has) would have turned each into about a tenth of that.
4. **Angular docs without Web Components leftovers.** The Angular badge doc has `igc-badge`, `::part(base)` and an
   empty Do/Don't table; the stepper and chip docs mix `*ngFor` and `[ngClass]` with the Angular-22 `@for` style.
5. **`mcp:get_api_reference?...component=IgxStep` links that resolve.** The stepper doc's links name `IgxStep` and
   `IgxStepper`; only `IgxStepComponent` and `IgxStepperComponent` exist.
6. **A doc for `igc-theme-provider`**, and a line in `themes-overview` that `configureTheme` is global while the
   provider scopes a theme and whether the grid components follow it. Grid Lite does not.
7. **A doc for Grid Lite theming of cell templates** (`adopt-root-styles`, how document CSS reaches a template
   inside the shadow root). It decides whether a template can be styled from a normal stylesheet.
8. **Known-issues in the docs.** Two defects cost time here and are in no answer: the stepper's `NaN` for steps in a
   loop, and the tile manager throwing when a tile is added before it has rendered.
9. **`detect_platform` that says where it looked**, and a `packageJsonPath` described as relative to the server's
   folder. With `.mcp.json` in a parent folder the default call fails for an app in a subfolder.
10. **A list of internal icon aliases that is complete**, including the chip's `remove`, instead of `<!-- ... -->`.
11. **`apexcharts_generate_config` with a `data` shape for a datetime axis**, so the placeholder categories do not
    have to be thrown away. Also, a version line in each answer ("skill verified against 8.8.1, project has 8.7.0").
12. **`resolve_import`** was the best call of the three servers: small, exact, platform-aware. The same style for
    "which CSS variable or token does this" would be the most useful thing to add.
